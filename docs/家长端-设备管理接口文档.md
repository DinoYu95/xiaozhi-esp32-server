# 家长端设备管理接口文档（小程序端）

针对「管理家中的机器人」这类界面，小程序可调用的接口汇总如下。  
**鉴权**：所有接口需请求头 `Authorization: Bearer {token}`。  
**基础地址**：`{baseUrl}`，如 `http://xxx:8002/xiaozhi`。

---

## 一、当前家长绑定的设备

### 1.1 设备列表（已实现）

| 项目 | 说明 |
|------|------|
| **URL** | `GET /parent-api/device/list` |
| **说明** | 返回当前家长绑定的所有设备 |
| **响应** | 见下方字段说明 |

**返回字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| deviceId | string | 设备 ID（MAC） |
| deviceName | string | 展示名称：主孩子名+「的机器人」，无主孩子时为「我的机器人」 |
| ownerChildName | string | 主孩子名字 |
| bindTime | string | 绑定时间 |
| lastConnectedAt | string | 最后连接时间 |
| isOnline | boolean | 是否在线（5 分钟内有连接视为在线） |
| batteryLevel | number | 电量百分比，设备未上报时占位为 0，后续设备上报后替换 |
| wifiName | string | 当前 WiFi 名称，设备未上报时占位为 \"--\"，后续设备上报后替换 |

**响应示例**：

```json
{
  "code": 0,
  "data": [
    {
      "deviceId": "AA:BB:CC:DD:EE:FF",
      "deviceName": "大宝的机器人",
      "ownerChildName": "大宝",
      "bindTime": "2025-02-13T10:00:00",
      "lastConnectedAt": "2025-02-13T15:30:00",
      "isOnline": true,
      "batteryLevel": 0,
      "wifiName": "--"
    }
  ]
}
```

### 1.2 绑定设备

| 项目 | 说明 |
|------|------|
| **URL** | `POST /parent-api/device/bind` |
| **请求体** | `{ "code": "123456" }`（设备屏上的 6 位绑定码） |
| **响应** | `{ "code": 0, "data": { "deviceId": "AA:BB:CC:DD:EE:FF", "message": "绑定成功" } }` |

---

### 1.3 解绑设备

| 项目 | 说明 |
|------|------|
| **URL** | `POST /parent-api/device/unbind` |
| **请求体** | `{ "deviceId": "AA:BB:CC:DD:EE:FF" }` |
| **响应** | `{ "code": 0 }` |

---

### 1.4 设备技能列表

| 项目 | 说明 |
|------|------|
| **URL** | `GET /parent-api/device/{deviceId}/skills` 或 `GET /parent-api/device/skills?deviceId={deviceId}` |
| **说明** | 获取某设备下所有技能（智控台配置的 speaker→skill 绑定） |
| **注意** | deviceId 含冒号时：① 用 query 方式更稳妥：`/skills?deviceId=B6:C8:35:D6:10:48`；② 用 path 时勿对 deviceId 二次 encode，后端会自动 decode |
| **响应** | `{ "code": 0, "data": [{ "skillId", "skillSource", "name", "description", "speakerTypes", ... }] }` |
| **skillId** | 官方=ai_skill.id（string），家长=parent_user_skill.id（number），与 search 返回的 id 一致 |
| **skillSource** | "official" \| "parent" |

## 五、在线状态 / 电量 / WiFi 处理方案

### 在线状态（已实现）

- 逻辑：设备通过 WebSocket/MQTT 与后端通信时更新 `ai_device.last_connected_at`
- 判断：若 `lastConnectedAt` 在 5 分钟内，则 `isOnline = true`
- 限制：依赖设备正常上报连接，若设备未连接过则始终为 offline

### 电量、WiFi（需设备上报）

当前 `batteryLevel`、`wifiName` 为占位值（0、"--"），因后端暂无设备上报数据源。

**实现思路**：

1. **设备端上报**：设备在连接/心跳时，将电量、WiFi 等信息上报到后端
2. **存储**：可写入 Redis（如 `device:status:{deviceId}`，TTL 约 5 分钟）
3. **接口**：在 `GET /parent-api/device/list` 中从 Redis 读取并填充 `batteryLevel`、`wifiName`

**设备端需配合**：

- 在 MQTT/WebSocket 心跳或 `get_device_status` 的应答里附带 battery、wifi 等信息
- 由 xiaozhi-server 或 MQTT 网关将上述信息写入 Redis，供 manager-api 读取

目前接口已返回占位值（batteryLevel=0, wifiName="--"），小程序可正常展示，后续接入设备上报后会自动替换为真实数据。
