# 家长端聊天接口 - 小程序调用说明

本文档说明小程序如何调用家长端「陪伴」页的聊天功能（家长与宝宝的专属小助手对话）。所有接口均在 **manager-api** 的 `parent-api` 下，需携带家长登录 token。

**推荐**：使用 **WebSocket 流式对话**（2.5 节）获得实时打字机效果；原有 HTTP 接口（2.2 节）仍可用。

---

## 一、前置条件

1. 家长已登录，持有 `token`（从 `POST /parent-api/auth/wechat` 等获取）
2. 已绑定设备，且设备有主孩子
3. 智控台「参数字典」中配置：
   - `xiaozhi.server.url`：xiaozhi-server 的 HTTP 地址，如 `http://172.21.0.163:8003`
   - `zhiban_agent.base_url`（在 xiaozhi-server 配置）：智伴 Agent 地址

---

## 二、连接方式

家长端支持两种方式：

| 方式 | 说明 | 适用场景 |
|------|------|----------|
| **WebSocket**（推荐） | 小程序直连 xiaozhi-server 的 WebSocket | 流式回复，实时体验好 |
| **HTTP** | 经 manager-api 的 `POST /parent-api/chat/send` | 简单场景，无需直连 |

**WebSocket 直连说明**：小程序连接 xiaozhi-server 的 HTTP 端口（默认 8003），路径 `/parent/chat/ws`。需确保：
- xiaozhi-server 对小程序可访问（如通过 nginx 暴露 8003 端口）
- xiaozhi-server 的 `data/.config.yaml` 中配置了 `manager-api.url` 和 `manager-api.secret`（用于 token 校验及聊天记录保存）

---

## 三、WebSocket 直连（推荐）

### 3.1 连接地址

```
ws://{xiaozhi-server-host}:{http_port}/parent/chat/ws?token={家长token}
```

例如：`ws://192.168.1.100:8003/parent/chat/ws?token=xxx`  
若使用 wss，则：`wss://your-domain.com/parent/chat/ws?token=xxx`

### 3.2 消息格式

**上行（小程序 → 服务端）**：

```json
{
  "childId": 1,
  "content": "宝宝今天和机器人聊了什么？",
  "audioId": null
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| childId | 是 | 主孩子 ID |
| content | 是 | 文本内容 |
| audioId | 否 | 语音消息的 audioId（需先通过 manager-api 上传） |

**下行（服务端 → 小程序）**：

- 流式 chunk：`{"type": "chunk", "chunk": "你"}`
- 结束：`{"type": "done"}`
- 错误：`{"type": "error", "message": "错误信息"}`

### 3.3 小程序示例

```javascript
// 连接（baseUrl 为 xiaozhi-server 的 ws 地址，如 ws://192.168.1.100:8003）
const wsUrl = (baseUrl || 'ws://localhost:8003').replace(/^http/, 'ws') + '/parent/chat/ws?token=' + token;
const socketTask = wx.connectSocket({ url: wsUrl });

socketTask.onMessage(res => {
  const msg = JSON.parse(res.data);
  if (msg.type === 'chunk') {
    appendToCurrentReply(msg.chunk);  // 逐字追加到当前回复
  } else if (msg.type === 'done') {
    finalizeMessage();
  } else if (msg.type === 'error') {
    showError(msg.message);
  }
});

// 发送消息
socketTask.send({ data: JSON.stringify({
  childId: 1,
  content: '宝宝今天和机器人聊了什么？',
  audioId: null
}) });
```

## 四、HTTP 接口（经 manager-api）

### 4.1 获取聊天历史（进入陪伴页时调用）

| 项目 | 说明 |
|------|------|
| 方法 | `GET` |
| 路径 | `{baseUrl}/parent-api/chat/history` |
| Query | `childId`（必填，主孩子 ID，来自「获取设备主孩子」接口的 `data.id`） |
| Header | `Authorization: Bearer {token}` |

**响应示例**：

```json
{
  "code": 0,
  "msg": "success",
  "data": [
    {
      "id": 1,
      "chatType": 1,
      "content": "宝宝今天和机器人聊了什么？",
      "audioId": null,
      "createTime": "2026-03-13T23:30:00"
    },
    {
      "id": 2,
      "chatType": 2,
      "content": "宝宝今天问了3个关于宇宙的问题，下午还玩了成语接龙~",
      "audioId": null,
      "createTime": "2026-03-13T23:30:05"
    }
  ]
}
```

| 字段 | 说明 |
|------|------|
| chatType | 1=家长，2=助手 |
| audioId | 非空表示该条为语音消息，可调用 2.4 获取播放 URL |

---

### 2.2 发送消息（文字）

| 项目 | 说明 |
|------|------|
| 方法 | `POST` |
| 路径 | `{baseUrl}/parent-api/chat/send` |
| Header | `Authorization: Bearer {token}` |
| Content-Type | `application/json` |

**请求体**：

```json
{
  "childId": 1,
  "content": "宝宝今天和机器人聊了什么？"
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| childId | 是 | 主孩子 ID |
| content | 是 | 文本内容（当前仅支持文字，语音需客户端先转文字） |
| audioId | 否 | 若为语音消息，可传 2.3 返回的 audioId，用于历史展示时可播放原语音 |

**响应示例**：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "id": 2,
    "chatType": 2,
    "content": "宝宝今天问了3个关于宇宙的问题，下午还玩了成语接龙~",
    "audioId": null,
    "createTime": "2026-03-13T23:30:05"
  }
}
```

`data` 为助手的回复消息，可直接追加到聊天列表展示。

---

### 2.3 上传语音（可选，用于发送带原声的消息）

若希望消息带语音回放（如录音后转文字发送），可先上传音频拿到 `audioId`，再在 2.2 中传入。

| 项目 | 说明 |
|------|------|
| 方法 | `POST` |
| 路径 | `{baseUrl}/parent-api/chat/upload-audio` |
| Content-Type | `multipart/form-data` |
| Header | `Authorization: Bearer {token}` |
| 参数 | `childId`（必填）、`file`（音频文件，≤10MB） |

**响应示例**：

```json
{
  "code": 0,
  "msg": "success",
  "data": "a1b2c3d4-e5f6-7890-abcd-ef1234567890"
}
```

`data` 为 `audioId`，用于 2.2 的 `audioId` 字段。**注意**：当前服务端不做 ASR，`content` 仍需由客户端（如微信语音识别）提供。

---

### 2.4 获取聊天语音播放 URL（播放历史中的语音消息）

| 项目 | 说明 |
|------|------|
| 方法 | `POST` |
| 路径 | `{baseUrl}/parent-api/chat/play-token` |
| Query | `audioId`（必填，来自 2.1 的 `data[].audioId`） |
| Header | `Authorization: Bearer {token}` |

**响应示例**：

```json
{
  "code": 0,
  "msg": "success",
  "data": "uuid-token-xxx"
}
```

播放 URL：`{baseUrl}/parent-api/chat/play/{data}`，直接 GET 即可，一次性使用后失效。可用于 `wx.createInnerAudioContext().src`。

## 三、页面流程示例

```
进入「陪伴 · 大宝」页
  → GET /parent-api/chat/history?childId=1
  → 渲染历史消息

用户输入文字并点击发送
  → POST /parent-api/chat/send { childId: 1, content: "..." }
  → 将返回的 data（助手消息）追加到列表

用户录音后发送（语音转文字）
  → 1. 客户端 ASR 得到文字
  → 2. 可选：POST /parent-api/chat/upload-audio（childId + file）
  → 3. POST /parent-api/chat/send { childId, content, audioId? }
  → 追加到列表

用户点击某条语音消息的播放
  → POST /parent-api/chat/play-token?audioId=xxx
  → 拿到 token 后，设置 InnerAudioContext.src = baseUrl + "/parent-api/chat/play/" + token
  → 播放
```

## 四、错误与边界

| 情况 | 处理 |
|------|------|
| 401 | token 无效或过期，跳转登录 |
| 孩子不存在 | 提示「孩子不存在」 |
| 设备未绑定 | 提示「设备未绑定或不属于当前家长」 |
| 设备无智能体 | 提示「设备未配置智能体」 |
| xiaozhi.server.url 未配置 | 助手会返回「抱歉，小助手暂时无法回复」 |

## 六、需补充或确认的点

### 6.1 孩子列表来源

**已确认**：从「设备列表 + 设备主孩子」接口获取。

- **一设备一主孩子**：每台设备在 `device_child` 表中至多一条记录。
- **多设备多主孩子**：家长可绑定多台设备，每台设备有各自的主孩子。
- **获取 children 列表**：先 `GET /parent-api/device/list` 得到设备列表；再对每个设备调用 `GET /parent-api/device/child?deviceId=xxx` 获取主孩子详情（含 `id`、`name` 等），`id` 即为聊天接口的 `childId`。
- 若需「汇总所有主孩子」的便捷接口，可后续新增 `GET /parent-api/device/children` 聚合返回。

### 6.2 xiaozhi.server.url 与 WebSocket 地址下发

**现状**：

- `xiaozhi.server.url` 在智控台「参数字典」配置，存于 `sys_params`。
- 该参数主要用于 **manager-api 内部** 调用 xiaozhi-server（如 HTTP 聊天接口）。
- **小程序 WebSocket 直连** 需要的 ws 地址（如 `ws://host:8003`）**尚未**通过 manager-api 接口下发给小程序。

**建议**：

- **短期**：小程序端写死或通过环境配置（如 `config.js`）获取 xiaozhi-server 的 ws 地址。
- **后续**：可新增 `GET /parent-api/config` 或扩展 `pub-config`，下发 `xiaozhiServerWsUrl`，供小程序动态连接。

### 6.3 今日简报

**现状**：无独立「今日简报」接口，companion 页当前使用本地 mock 数据。

**建议**：先维持 mock；若需真实数据，可后续设计独立接口（如基于设备聊天记录、情境记忆等生成简报）。

### 6.4 语音识别（ASR）

**已确认**：服务端不做 ASR，`content` 必须由客户端提供。

- 录音发送流程：`wx.getRecorderManager()` 录音 → 通过**微信语音识别**（如 `PluginRecord`、`wx.getVoiceRecorderManager` 等）或**自研/第三方 ASR** 得到文字 → 将 `content` 传给 `POST /parent-api/chat/send` 或 WebSocket。
- 若为语音消息且需回放，可先 `POST /parent-api/chat/upload-audio` 上传原声，再在 send 时传入 `audioId`。

### 6.5 高情商传话

**已确认**：由现有 `/parent-api/chat/send`（及 WebSocket）背后的逻辑统一处理，无单独接口。

- 家长发送的文本经 xiaozhi-server 传入 zhiban-agent。
- 「高情商转化」「传话」等效果由 **zhiban-agent 的 system prompt / 技能** 决定，无需额外接口或流程。

### 6.6 家长专用 skill 配置

家长通过小程序对话时，应固定使用一个**家长专项 skill**，用于辅助家长管理孩子、汇报孩子近期情况、回答家长关于孩子状态的问题。

**配置步骤**：

1. 在智控台「技能管理」中创建或编辑一个技能，命名为如「家长育儿助手」。
2. 在「角色配置」中，将该技能映射到说话人类型 `parent`（家长），确保家长对话时始终使用该 skill。
3. **Skill instructions 推荐内容**（可据此填写技能说明）：

   > 你是家长的育儿助手。当家长通过小程序与你对话时，你的职责包括：
   > - 辅助家长了解和管理孩子的情况；
   > - 汇报孩子近期与助手的对话情况；
   > - 回答家长关于孩子近况、学习、兴趣等的问题。
   > 
   > 你会收到【孩子与助手的近期对话】上下文。当家长询问孩子近期情况时，请结合该对话记录进行汇总汇报，用温暖、有分寸的语言向家长传达。

**技术实现**：manager-api 会拉取该设备（孩子）在 `ai_agent_chat_history` 中近期的对话记录（约 30 条），格式化为「孩子：xxx\n助手：yyy」传入 `environment_context.child_recent_chat_history`，由 xiaozhi-server 注入到发给 zhiban-agent 的文本中。需确保设备已开启 `chat_history_conf`（智控台智能体配置中「聊天记录」开启），设备与助手的对话才会被上报入库。

### 6.6 家长专用 skill 配置

**功能说明**：家长通过小程序与智伴对话时，应固定使用一个专项 skill，用于辅助家长管理孩子、汇报孩子近期情况、回答家长关于孩子状态等问题。系统会自动拉取孩子与助手的近期对话记录（来自 `ai_agent_chat_history`），汇总后传入智伴，供其回答家长关于「宝宝今天聊了什么」等提问。

**智控台配置**：

1. 在「角色配置」中为 **说话人类型 = parent** 配置并绑定一个技能（如 `skill_parent_assistant`）。
2. 该技能的 **instructions** 建议包含以下要点：
   - 你是家长的育儿助手，协助家长了解和管理孩子；
   - 当家长询问孩子近期情况时，请结合传入的【孩子与助手的近期对话】进行汇总汇报；
   - 可适度做「高情商传话」，将孩子的表达转化为家长易理解的表述；
   - 注意保护孩子隐私，不泄露敏感信息。

**依赖条件**：

- 智控台「智能体配置」中需开启 `chat_history_conf`（1 或 2），设备与助手的对话才会写入 `ai_agent_chat_history`；
- 设备需有正确的 `mac_address`，以便按设备查询孩子的对话记录。

### 6.6 家长专用 skill 配置

家长通过小程序对话时，应使用**固定专项 skill**，用于辅助家长管理孩子、汇报孩子情况、回答家长关于孩子近期状态等。

**智控台配置**：在「角色配置」中为 `speaker_type=parent` 配置对应 skill，并在该 skill 的 instructions 中写明：

- **职责**：你是家长的育儿助手，通过小程序与家长对话。主要职责包括：
  1. 辅助家长了解和管理孩子；
  2. 汇报孩子近期与助手对话的情况；
  3. 回答家长关于孩子近况、兴趣、学习状态等问题。

- **数据来源**：当家长询问孩子近期情况时，你会收到【孩子与助手的近期对话】。该内容由系统自动拉取自 `ai_agent_chat_history`（设备与该智能体的最近 30 条对话），请结合该对话进行汇总、提炼后回答家长。

- **示例 instructions**（可粘贴到 skill 的 instructions 字段）：
  ```
  你是家长专用育儿助手。当家长通过小程序与你对话时，请：
  1. 根据【助手已知信息】中的家长昵称、孩子姓名等，正确称呼和应答；
  2. 当家长询问孩子近期情况（如「宝宝今天和机器人聊了什么」「孩子最近在学什么」）时，结合【孩子与助手的近期对话】进行汇总汇报，做到有理有据、简洁清晰；
  3. 可适当给出育儿建议，语气温和、专业。
  ```

**前置条件**：智能体的「聊天记录上报」需开启（chat_history_conf 为 1 或 2），设备与孩子的对话才会写入 `ai_agent_chat_history`，家长端才能拉取到孩子近期对话。

### 6.6 家长专用 skill 配置

家长通过小程序对话时，应使用**固定专项 skill**，用于辅助家长管理孩子、汇报孩子情况、回答家长关于孩子近期状态等问题。

**智控台配置**：在「角色配置」中为该智能体添加 **speaker_type=parent** 的技能映射，并创建或指定一个 skill，推荐 instructions 如下：

```
你是家长的育儿助手。你的对话对象是孩子的家长，家长通过小程序与你对话。

你的能力包括：
1. 辅助家长了解和管理孩子的使用情况；
2. 汇报孩子近期与助手的互动情况；
3. 当家长询问「孩子今天聊了什么」「最近和机器人说了啥」等问题时，请结合【孩子与助手的近期对话】进行汇总汇报。

系统会为你提供孩子的近期对话记录（格式为「孩子：xxx」「助手：yyy」），请据此做有温度的汇总，而非逐条复述。
```

**数据流**：当家长发起对话时，manager-api 会：
- 根据 device_id 获取设备 mac_address；
- 从 `ai_agent_chat_history` 拉取该设备（孩子）与助手的最近 30 条对话；
- 格式化后放入 `environment_context.child_recent_chat_history` 传给 xiaozhi-server；
- xiaozhi-server 将其注入到用户文本前，供 zhiban-agent 回答。

**前置条件**：智能体需开启 `chat_history_conf`（1 或 2），设备上报的对话才会写入 `ai_agent_chat_history`。

### 6.6 家长专用 Skill 配置

家长通过小程序对话时，应固定使用一个专项 skill，用于辅助家长管理孩子、汇报孩子近期情况、回答家长关于孩子状态的问题。

**智控台配置步骤**：

1. 在「技能管理」中创建或选用一个技能，建议命名为「家长育儿助手」。
2. 在「角色配置」中将该技能映射到 `speaker_type=parent`。
3. 技能 instructions 建议包含以下说明：

```
你是家长的育儿助手，当家长通过小程序与你对话时，你的职责包括：
- 辅助家长了解和管理孩子的成长情况；
- 汇报孩子与助手的近期互动、学习与娱乐情况；
```

**技术实现**：
