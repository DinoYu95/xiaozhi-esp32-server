# 多角色与智伴 Agent — 部署与验证

## 一、需要执行的操作

### 1. 数据库（二选一）

**方式 A：用 Liquibase 自动执行（推荐）**

- 启动 **manager-api** 时，若已配置 Liquibase，会按 `db.changelog-master.yaml` 自动执行未执行过的 changeSet。
- 本特性对应：`202602131600.sql`（表 `ai_skill`、`ai_agent_skill_mapping`）、`202602131700.sql`（一说话人对应多技能：允许同一说话人类型绑定多个 skill_id，由意图选 skill）。
- 无需手跑 SQL，只要保证数据库连接正确、应用能正常启动即可。

**方式 B：手动执行 SQL（未用 Liquibase 或想先建表）**

在**智控台使用的 MySQL** 里执行下面整段：

```sql
-- 多角色与智伴 Agent 适配：技能表 + 智能体说话人类型→技能映射表
CREATE TABLE IF NOT EXISTS `ai_skill` (
    `id` VARCHAR(64) NOT NULL COMMENT '技能唯一标识，如 skill_children_chat',
    `name` VARCHAR(128) NOT NULL COMMENT '展示名称',
    `description` VARCHAR(512) DEFAULT NULL COMMENT '简短用途说明',
    `instructions` TEXT NOT NULL COMMENT '技能说明/系统级提示',
    `version` VARCHAR(32) DEFAULT '1.0' COMMENT '版本号',
    `tools` JSON DEFAULT NULL COMMENT '该技能可用的工具 id 列表',
    `metadata` JSON DEFAULT NULL COMMENT '扩展字段',
    `create_time` DATETIME DEFAULT NULL COMMENT '创建时间',
    `update_time` DATETIME DEFAULT NULL COMMENT '更新时间',
    PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='技能定义表';

CREATE TABLE IF NOT EXISTS `ai_agent_skill_mapping` (
    `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键',
    `agent_id` VARCHAR(32) NOT NULL COMMENT '智能体ID',
    `speaker_type` VARCHAR(32) NOT NULL COMMENT '说话人类型: owner_child/parent/other_child/other_adult/unknown',
    `skill_id` VARCHAR(64) NOT NULL COMMENT '技能ID',
    `create_time` DATETIME DEFAULT NULL COMMENT '创建时间',
    `update_time` DATETIME DEFAULT NULL COMMENT '更新时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_agent_speaker` (`agent_id`, `speaker_type`),
    KEY `idx_agent_id` (`agent_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='智能体说话人类型→技能映射表';

-- 一说话人对应多技能（执行完上表创建后执行）：
ALTER TABLE `ai_agent_skill_mapping` DROP INDEX `uk_agent_speaker`;
ALTER TABLE `ai_agent_skill_mapping` ADD UNIQUE KEY `uk_agent_speaker_skill` (`agent_id`, `speaker_type`, `skill_id`);
```

### 2. 服务启动

- **manager-api**：正常启动（确保连到上面执行过 SQL 的库）。
- **manager-web**：正常启动/打包部署，保证能访问智控台。
- **xiaozhi-server**：正常启动，能连到智控台拉配置、连 zhiban-agent。
- **zhiban-agent**：若已按设计接好 `speaker_context` / `skill_id` / `environment_context`，需一起启动以便端到端验证。

无需额外脚本或环境变量（沿用现有配置即可）。

## 二、如何验证改动

### 1. 技能管理（智控台）

1. 用**超级管理员**账号登录智控台。
2. 顶栏 **「参数与字典」** → **「技能管理」**，应进入 `/skill-management` 页面。
3. **新建技能**：点击「新建技能」，填写：
   - 技能ID：如 `skill_children_chat`
   - 名称：如「儿童对话」
   - 说明：可选
   - 系统提示：必填，如「你是一位面向儿童的陪伴助手，语气亲切、用词简单。」
   - 版本：如 `1.0`
4. 保存后，列表中应出现该技能；可再**编辑**、**删除**做一次验证。

**重要**：**一个说话人可以对应多个技能**。在角色配置的「说话人→技能」里，每类说话人（主孩子/家长/其他孩子/其他成人/未知）可**多选**多个技能；对话时由 **zhiban-agent 根据用户意图** 从该说话人允许的 skill 列表中选一个执行。智控台中的 skill_id 需与 zhiban-agent 里已实现的 node 标识一致。请先在「技能管理」里为每个 zhiban node 建好 skill（含完整 instructions），再在角色配置里为每类说话人勾选其可用的多个技能。

**新建技能表单字段说明**

| 字段 | 是否必填 | 说明 |
|------|----------|------|
| **技能ID** | 必填 | 与 zhiban-agent node 标识一致，创建后不可改 |
| **名称** | 必填 | 展示用名称，在「说话人→技能」下拉里显示 |
| **说明** | 选填 | 简短用途说明，列表页展示 |
| **系统提示** | 必填 | 即 instructions，发给模型的技能说明，**每条 skill 都必须填写完整** |
| **版本** | 选填 | 版本号，如 `1.0` |

**与 zhiban-agent 节点对应的 Skill 一览（建议映射）**

每类说话人可**多选**下表中多个 skill（例如主孩子可同时选「儿童对话」「讲故事」），请求时 xiaozhi 传 **skill_ids** 列表，zhiban-agent 按**意图**从列表中选一个 skill 执行。

| zhiban-agent node（建议） | skill_id | 名称 | 建议可选的说话人 |
|---------------------------|----------|------|------------------|
| 儿童对话 | skill_children_chat | 儿童对话 | owner_child |
| 讲故事 | skill_storytelling | 讲故事 | owner_child, other_child |
| 家长控制 | skill_parent_control | 家长控制 | parent |
| 访客（通用） | skill_guest | 访客 | other_child, other_adult, unknown |
| 访客孩子 | skill_guest_child | 访客孩子 | other_child |
| 访客成人 | skill_guest_adult | 访客成人 | other_adult |
| 通用闲聊 | skill_general_chat | 通用闲聊 | unknown |

以下**每条 skill 均给出完整表单数据**（技能ID、名称、说明、系统提示 instructions），可直接在智控台「新建技能」中粘贴使用；**系统提示**必须完整填写，不能省略。

| 表单字段 | 填写内容 |

**系统提示（instructions）**（推荐使用，可避免重复同一谜语、答对后立刻告别、括号旁白等问题）：

```
你是面向儿童的互动游戏助手。可以和小朋友玩猜谜语、脑筋急转弯、词语接龙、数字小游戏等。

规则：
1. 每次用户说「玩游戏」时，先问想玩哪种：猜谜语、词语接龙、数字游戏还是脑筋急转弯；不要每次都直接出谜语。
2. 出谜语时变换不同主题（动物、植物、日常物品、交通工具等），不要重复同一道谜语。
3. 题目适合儿童认知，难度适中；出题后适当提示或等待回答，答对时热情鼓励。
4. 答对后不要主动说再见、下次再玩、时间过得真快等告别语；应先问「要再玩一局吗？」。只有孩子明确说「不玩了」「拜拜」等时，才可以说再见。
5. 回复中不要包含括号内的动作描写（如（轻轻拍拍）），只输出要对孩子口述的内容。
6. 语气活泼、有趣。若孩子明确表示不想玩了，可自然结束或换话题。
```

1. 用**真实设备**或**模拟客户端**向智控台拉取该智能体的私有配置（即 getAgentModels 或你们现有的「拉配置」接口）。
2. 在返回的 JSON 中检查是否包含：

- **声纹**：设备上报带声纹的音频，xiaozhi 识别后应设置 `conn.current_speaker_id`、`current_speaker`，并在合适逻辑里设置 `current_round_speaker_type`（如 owner_child / other_child）。

- **记忆**：不同说话人应有不同 `role_id`，每轮 chat 前 `memory.switch_role(role_id)`，对话内容按人隔离。

可在 xiaozhi-server 日志中搜索 `speaker_context`、`skill_ids`、`environment_context`、`switch_role` 等关键字，确认这些字段被正确拼装与传递。

### 5. zhiban-agent（若已联调）

- 在 zhiban 请求体或日志中确认收到：
  - `speaker_context`（当前说话人信息），
  - **`skill_ids`**（当前说话人可用的 skill 列表，数组），
  - `environment_context`（环境信息）。
- zhiban-agent 应根据**用户意图**从 `skill_ids` 中选一个 skill 执行（意图路由），回复风格/技能内容随选中的 skill 与 `speaker_context` 变化。

### 6. zhiban-agent：Skill 唯一数据源是智控台，nodes 文件夹与 skill 的关系

**结论**：**Skill 的文案（instructions）以智控台为准**。zhiban-agent 已改为接收 `skill_ids`、按图内 **router 的 intent**（knowledge_qa/game/story/other）从 skill_ids 中选一个 `skill_id`，再向 **manager-api** 拉取 `GET /agent/skill/{id}` 取 instructions 注入 system。nodes 文件夹**保留**，但只负责「意图路由 + 记忆加载/保存」等图逻辑，**不再**提供技能文案。

| zhiban-agent 里 | 作用 | 是否保留 |
|-----------------|------|----------|
| **nodes/router.py** | 意图分类（knowledge_qa / game / story / other），用于从 skill_ids 中优先选匹配的 skill_id，以及 save_memory 的 intent 维度 | 保留 |
| **nodes/load_memory.py、save_memory.py** | 长期记忆加载与写入 | 保留 |
| **graph 里 knowledge_qa、game、story、other 四个节点** | 当前为占位（_agent_node），实际回复在 main 里用 LLM + 智控台拉取的 skill instructions 生成 | 保留图结构即可，不提供文案 |
| **技能文案（instructions）** | 来自智控台：请求时调 manager-api `GET …/config/agent/skill/{id}`（server secret 鉴权），用返回的 instructions 拼进 system | 不从 nodes 读 |

**zhiban-agent 已实现的改动**（与 xiaozhi 同分支 feature/multi-role-zhiban-agent）：

1. **ChatRequest**：增加 `skill_ids: Optional[List[str]]`；兼容原有 `skill_id`。
2. **解析 skill_id**：`_resolve_skill_id(skill_ids, skill_id, intent)`：有 skill_ids 时按 intent 优先匹配（如 intent=story 且 skill_ids 含 skill_storytelling 则选它），否则取第一个；无则用 skill_id。
3. **拉取 instructions**：`_fetch_skill_instructions(skill_id)` 调 `GET {MANAGER_API_BASE}/config/agent/skill/{id}`，请求头带 `Authorization: Bearer {MANAGER_API_SECRET}`，取 `data.instructions` 注入 system。
4. **_build_system_message**：增加 `skill_instructions` 参数；有则拼「## 技能说明（请严格遵循）」段，无则仅保留「当前技能ID」占位。

**zhiban-agent 环境变量（必配才能拉到 instructions）**：

| 变量 | 说明 | 示例 |
|------|------|------|
| **MANAGER_API_BASE** | 智控台 manager-api 根地址（与 xiaozhi 拉配置同一服务） | `http://127.0.0.1:8002/xiaozhi` |
| **MANAGER_API_SECRET** | 智控台「系统参数」里的 **server_secret**（与 xiaozhi、设备拉配置用同一密钥） | 在智控台 参数管理 → 系统参数 中查看/设置 |

只配 `MANAGER_API_BASE` 不配 **MANAGER_API_SECRET** 时，请求 `/config/agent/skill/{id}` 会返回 401，拉不到 instructions，system 里只有「当前技能ID」占位。两样都配齐即可。

这样智控台改 skill 文案后，zhiban 下次请求即拉取最新 instructions，**单一数据源**；nodes 只做意图与记忆，不做技能文案。

## 五、联调中常见问题与修复

### 5.1 用户说话被忽略、未调用 zhiban-agent，或莫名断连

**现象**：用户说了话，xiaozhi 日志显示 ASR 识别到了文本，但没有调用 zhiban，或过一段时间自动说结束语断连。

**原因**：多角色打断策略中，当声纹识别**失败**（相似度低于阈值，返回「未知说话人」）时，`speaker_id` 为 `None`，被当作「非主孩子声音」而忽略。实为同一孩子在嘈杂/远距离下声纹匹配失败，导致其回复被丢弃。

**修复**：已在 `xiaozhi-server/core/providers/asr/base.py` 中调整逻辑：当 `speaker_id is None` 且为「未知说话人」时，**不再忽略**，仍按正常流程处理，避免对话断连。

### 5.2 用户问「谜语答案/提示」，助手答非所问或跑题成告别语

**原因**：

1. **上游被忽略**：用户说「不知道」时，若声纹失败，该轮被丢弃，zhiban 从未收到。
2. **无会话上下文**：zhiban 每次请求只接收**当前一句**用户文本，不包含历史多轮对话。因此收到「能给一点提示吗」时，无法知道「刚出了哪个谜语」，容易误解为其它场景（如告别、故事等）。

**修复**：已实现 xiaozhi 向 zhiban 传递**最近 N 轮对话**：

- **xiaozhi-server**（`core/providers/llm/ZhibanAgent/ZhibanAgent.py`）：从 dialogue 提取最近 3 轮（可配 `max_history_rounds`），构建 `messages` 数组 `[{"role":"user","content":"..."},{"role":"assistant","content":"..."},...]`，随请求发给 zhiban。
- **zhiban-agent**（`app/main.py`）：ChatRequest 增加 `messages` 字段；生成回复时若有 `messages`，则将其与 system 一起交给 LLM，使模型能看到完整对话（含谜语、用户要提示等），从而正确给出谜语提示而非跑题。

重启 xiaozhi-server 与 zhiban-agent 后，谜语场景的「给提示」「告诉我答案」等应能正确理解。

### 5.3 回复僵硬、未体现智控台技能说明

**现象**：zhiban-agent 日志中 `has_skill_instructions=False`，回复风格与智控台技能 instructions 不符。

**原因**：未配置或未正确配置 `MANAGER_API_BASE`、`MANAGER_API_SECRET`，导致从智控台拉取 skill instructions 失败（401 或未请求）。

**修复**：在 zhiban-agent 的 `.env` 中配置：

```
MANAGER_API_BASE=http://你的智控台地址/xiaozhi
MANAGER_API_SECRET=智控台「参数管理→系统参数」中的 server_secret
```

配置后重启 zhiban-agent，日志中应出现 `has_skill_instructions=True` 及 `_fetch_skill_instructions: skill_id=xxx 拉取成功`。

### 5.4 「主孩子轮次内非主孩子声音，忽略本段」日志频繁出现

**原因**：声纹识别相似度波动，同一孩子说话时偶尔低于阈值，被误判为他人。

**建议**：

- 确认已应用 5.1 修复（声纹失败时不再忽略）。
- 若仍频繁忽略：可适当**降低声纹相似度阈值**（voiceprint `similarity_threshold`），或检查麦克风/环境噪音。

### 5.5 「讲完故事后又重复解释原因」现象说明

**现象**：用户说「hello」→ 助手知道用户喜欢听故事（来自长期记忆）→ 用户问「你怎么知道我喜欢听故事」→ 助手先解释原因再讲故事 → 讲完故事后，又开始说一遍「知道你喜欢听故事的原因」等重复内容。

**可能原因**：

1. **单轮生成长回复时的自我重复**  
   模型在一轮里既要「解释原因」又要「讲故事」，生成长回复时容易在结尾再次总结或复述前文，出现「解释→故事→再解释」的结构。属于生成长度与指令遵循的常见问题。

2. **long_term_context 再次被强调**  
   `load_memory_node` 会把「喜欢听故事」等记忆注入到 system/context。若本轮 prompt 里既有「用户问：你怎么知道」又有「长期记忆：孩子喜欢听故事」，模型可能在讲完故事后又基于同一段记忆再答一遍「因为记忆里提到…」。

3. **无「不要重复前文」的约束**  
   当前 skill instructions 里若没有明确要求「不要重复前文已说过的原因或结论」，模型更容易在长回复末尾再总结一次。

**排查建议**：

- 看 zhiban-agent 日志里的 `long_term_context` 预览、`reply_len` 与 `reply_preview`，确认本轮注入的记忆内容和最终回复长度。
- 若确认是长回复自我重复，可在该技能的 **系统提示（instructions）** 里加一句约束，例如：「若你在同一条回复里已经解释过原因或讲完故事，不要在同一段回复末尾再次重复解释原因或重复结论。」
- 若希望「解释」与「讲故事」拆成两轮，可考虑在 product 上拆成「先短回复解释 + 再问是否要听故事」的流程，由多轮完成，减轻单轮生成长度压力。

### 5.6 TTS 报错「illegal input text!」、语音生成失败重试 5 次

**现象**：xiaozhi-server 日志出现 `语音生成失败1次: ），错误: core.providers.tts.doubao status_code: 400 response: ... "message":"illegal input text!"`，重试 5 次后仍失败。

**原因**：大模型流式输出中，有时会单独输出标点片段（如「对了，我就再出一个更难的」后紧跟「）」），流式分句后会产生**仅含标点**的片段（如「）」）。豆包等 TTS 不接受纯标点、过短或无效文本，会返回 `illegal input text!`。

**修复**：已在 xiaozhi-server 中：

1. **textUtils**（`core/utils/textUtils.py`）：在 `is_punctuation_or_emoji` 的 punctuation_set 中加入中文/英文括号 `（` `）` `(` `)`，使 `get_string_no_punctuation_or_emoji` 能将其 strip 掉，纯标点片段会变为空字符串。
2. **TTS base**（`core/providers/tts/base.py`）：在 `to_tts_stream`、`to_tts` 中，对文本先做 `get_string_no_punctuation_or_emoji`，若结果为空则直接返回，不再调用 TTS 接口。

这样纯「）」等片段会被过滤，避免 TTS 报错和无效重试。

### 5.7 使用 ZhibanAgent 时自动跳过意图识别（无需改智控台）

**现象**：智控台模型配置中 Intent 无法改为 nointent，导致每轮对话前仍调用意图 LLM，增加 20～40 秒延迟；日志出现「解析到说话人」与「llm 识别到意图」间隔 20+ 秒。

**修复**：已在 `xiaozhi-server/core/handle/intentHandler.py` 中增加逻辑：当 LLM 为 ZhibanAgent 时**自动跳过** intent_llm。判断方式兼容智控台下发的 model_id：除 `selected_module.LLM == "ZhibanAgent"` 外，还检查 `config.LLM[xxx].type` 与 `conn.llm` 实例类型。重启后日志应出现「LLM 为 ZhibanAgent，跳过意图识别，直接进入对话」。

后续若需 play_music、IoT 等能力，将在 zhiban-agent 内实现工具，由 zhiban 决策、xiaozhi 执行，不依赖 xiaozhi 的意图识别。

### 5.8 括号旁白被 TTS 念出、重复同一谜语、答对后立刻告别

**现象**：回复中出现「（轻轻拍拍你的小肩膀）」「（声音放轻，带点不舍）」等旁白被 TTS 念出；每次猜谜语都是同一道（如梁龙）；答对后立刻说「下次再玩」等告别语。

**修复**：

1. **括号旁白**：已在 `core/utils/tts.py` 的 MarkdownCleaner 中增加正则，移除含「轻轻、拍拍、摸摸、点头、叹气、声音放、带点」等关键词的括号内容，避免念出。
2. **重复谜语 / 答对后告别**：需在智控台 **skill_game** 的系统提示中补充约束，例如：
   - 每次用户说玩游戏时，先问想玩哪种（谜语/词语接龙/数字游戏/脑筋急转弯）；出谜语时变换主题，不要重复同一道。
   - 答对后不要主动告别；应先问「要再玩一局吗？」；只有孩子明确说「不玩了」「拜拜」等时才告别。
   - 回复中不要包含括号内的动作描写（如（轻轻拍拍）），只输出要对孩子口述的内容。

## 六、长期记忆（memory）存储验证

zhiban-agent 的长期记忆使用 **Postgres + PGVector**，与 LangChain 兼容。存储位置与字段含义如下，便于联调时直接查库或用脚本验证。

### 存储位置与表结构

- **数据库**：与 zhiban-agent 的 `POSTGRES_MEMORY_URL` 使用同一 Postgres 实例。
- **表**：LangChain 使用 `langchain_pg_embedding` 存向量与文档，通过 `langchain_pg_collection` 关联集合名。
- **集合名**：`zhiban_long_term_memory`（zhiban-agent 写记忆时固定使用该 collection）。
- **metadata 常用字段**：
  - `user_id`：用户/设备侧传入的 user_id，用于按用户隔离记忆。
  - `scope`：`global`（全局人设/偏好）或当前 agent 名（如 `storytelling`、`children_chat`），用于区分「全局事实」与「某技能下的事实」。

### 如何验证写入与查询

**方式一：直接 SQL 查 Postgres**

连接与 zhiban 相同的库后，可执行：

```sql
-- 某用户的全部记忆（内容、scope、id）
SELECT e.document AS 事实内容, e.cmetadata->>'user_id' AS user_id, e.cmetadata->>'scope' AS scope, e.uuid AS id
FROM langchain_pg_embedding e
JOIN langchain_pg_collection c ON e.collection_id = c.uuid
WHERE c.name = 'zhiban_long_term_memory' AND e.cmetadata->>'user_id' = '你的测试user_id'
ORDER BY e.document;

-- 该用户记忆条数（写前后对比）
SELECT COUNT(*) FROM langchain_pg_embedding e
JOIN langchain_pg_collection c ON e.collection_id = c.uuid
WHERE c.name = 'zhiban_long_term_memory' AND e.cmetadata->>'user_id' = '你的测试user_id';
```

对话前查一次条数，触发几轮「可被抽取为事实」的对话（如「我叫小明」「我喜欢听故事」）后再查一次，条数应增加；重复说同一事实时，冲突消解可能为 NOOP，条数可能不变。

**方式二：使用 zhiban-agent 项目脚本**

在 **zhiban-agent** 仓库根目录执行：

```bash
python scripts/query-long-term-memory.py
```

会列出每条记忆的事实内容、user_id、scope、id，便于快速确认是否写入了预期 user_id 和 scope。

**方式三：按 scope 查 game 等 agent 记忆（验证谜语是否写入）**

若每次都重复同一谜语，可查 game scope 是否写入了「出过的谜语」类事实：

```sql
-- 查某用户的 game scope 记忆（应含「孩子答对梁龙」「助手出过梁龙谜语」等）
SELECT e.document AS 事实内容, e.cmetadata->>'scope' AS scope, e.cmetadata->>'speaker_type' AS speaker_type
FROM langchain_pg_embedding e
JOIN langchain_pg_collection c ON e.collection_id = c.uuid
WHERE c.name = 'zhiban_long_term_memory'
  AND e.cmetadata->>'user_id' = '你的测试user_id'
  AND e.cmetadata->>'scope' = 'game'
ORDER BY e.document;
```

代码逻辑（zhiban-agent `app/graph/nodes/save_memory.py`）：含「玩过」「答对」「出过」「出题」等关键词的事实会写入 `scope=current_agent`（如 game）；EXTRACT_PROMPT 已增强，会抽取「助手出过的谜语/题目及答案」，便于下次不重复出同一道题。

**日志辅助**：zhiban-agent 已在 `load_memory_node` 打 `long_term_context` 长度与预览，在 `save_memory_node` 打本轮对话条数、最后一条 assistant 预览、抽取到的事实条数及每条 fact→scope；在 main 里 `_save_memory_after_reply` 打 user_id、intent、reply_len。联调时结合这些日志与上面 SQL/脚本，即可验证 memory 的读写是否符合预期。

更详细的查库说明见 zhiban-agent 仓库内文档：**长期记忆-如何查库验证.md**。

### 清空记忆（测试用）

需要清空长期记忆重新测试时，在 **Postgres**（与 zhiban 的 `POSTGRES_MEMORY_URL` 同一库）执行：

```sql
-- 清空全部长期记忆（慎用，会删除所有 user 的记忆）
DELETE FROM langchain_pg_embedding e
USING langchain_pg_collection c
WHERE e.collection_id = c.uuid
  AND c.name = 'zhiban_long_term_memory';

-- 仅清空某 user_id 的记忆（推荐，便于单用户回归）
DELETE FROM langchain_pg_embedding e
USING langchain_pg_collection c
WHERE e.collection_id = c.uuid
  AND c.name = 'zhiban_long_term_memory'
  AND e.cmetadata->>'user_id' = '你的测试user_id';
```

## 七、网页版对话测试步骤

网页版测试页面（test_page.html）可用来验证技能、记忆与端到端对话，无需真机或声纹。

### 1. 启动测试页面

```bash
cd main/xiaozhi-server/test
python -m http.server 8006
```

浏览器访问：**http://localhost:8006/test_page.html**

### 2. 前置准备（智控台）

1. **创建设备**（若尚无）：智控台首页添加设备，记下 **设备 MAC**（如 `AA:BB:CC:DD:EE:01`）。
2. **绑定智能体**：该设备需已绑定一个智能体（agent），且该 agent 的 LLM 选的是 ZhibanAgent。
3. **建技能并配置映射**：
   - 技能管理里至少建 **skill_children_chat**（儿童对话）、**skill_storytelling**（讲故事）；可选 skill_general_chat（通用闲聊）。
   - 角色配置里，给 **「未知」** 说话人多选：儿童对话、讲故事、通用闲聊（网页版无声纹，说话人默认为 unknown）。

### 3. 网页连接与对话

1. 点击 **「设置」**：OTA 服务器填智控台地址（如 `http://127.0.0.1:8002/xiaozhi/ota/`），设备 MAC 填智控台里的设备 MAC，客户端 ID 保持 `web_test_client` 或自填。
2. 点击 **「拨号」**：等待连接成功，状态变为「已连接」。
3. 在底部输入框输入文字，按 **Enter** 发送，或使用 **录音** 发送语音。

### 4. 对话测试速查表：怎么说能测到哪个功能

zhiban-agent 的 router 会把你的话归为 4 类意图，再按意图从 skill_ids 里选一个 skill。**你要做的**：按下面话术发一句，看回复风格是否符合对应技能。

**前置**：角色配置里给「未知」说话人多选至少这些 skill：`skill_children_chat`、`skill_storytelling`、`skill_game`、`skill_general_chat`（或 `skill_knowledge_qa`），否则某些意图会落到第一个 skill。

| 想测的功能 | 怎么说（示例） | 预期意图 | 会用的 skill |
|------------|----------------|----------|--------------|
| **讲故事** | 「给我讲个故事」「讲个小兔子的故事」「继续讲」 | story | skill_storytelling / skill_story |
| **知识问答** | 「太阳为什么是圆的」「为什么天会下雨」「恐龙为什么会灭绝」「什么是星星」 | knowledge_qa | skill_children_chat / skill_knowledge_qa |
| **玩游戏** | 「我们玩游戏吧」「玩猜谜语」「来玩脑筋急转弯」 | game | skill_game |
| **闲聊/寒暄** | 「你好呀」「hello」「在吗」「今天天气怎么样」 | other | skill_general_chat / skill_children_chat（或列表第一个） |

**更具体的话术建议**：

- **测 story**：直接说「给我讲个故事」或「讲个小兔子的故事」，回复应偏故事风格，有情节。
- **测 knowledge_qa**：说「太阳为什么是圆的」「为什么天会下雨」等带「为什么/是什么/怎么」的问句，回复应是科普式解答。
- **测 game**：说「我们玩游戏吧」「玩猜谜语」，回复应有出题或互动游戏的风格。
- **测 other**：说「你好」「hello」等寒暄，回复应简短、友好。

**验证方式**：看 zhiban-agent 日志里的 `intent` 和 `resolved skill_id`，确认和上表一致。

### 5. 测试 memory

1. 先清空该 user 的记忆（见上文「清空记忆」SQL，user_id 一般为 `设备id_客户端id` 或会话相关）。
2. 说「我喜欢听故事」→ 等待回复。
3. 新开一轮说「你知道我喜欢什么吗」→ 应能结合记忆回答「喜欢听故事」。
